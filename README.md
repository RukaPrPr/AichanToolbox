# 艾酱图片工具箱 7.6.4

方案三重构版本：C#/.NET 图片处理核心 + WPF 标准 WebView2 桌面外壳 + Vue 3/TypeScript 前端 + DOM 节点 + WebGL 连接线。连接层固定为视口大小，由 GPU 完整绘制并始终保留彩色光晕；拖动节点和画布时不再关闭毛玻璃或降低连线效果。

7.6.4 将节点从挂载开始就固定在同一 `translate3d` 坐标通道中；点击、开始拖动和松开只更新坐标，不再动态创建或清除 transform，也不再切换 `will-change` 合成提示，从而消除低缩放下节点文字粗细闪烁。

图片处理采用 libvips 解码、色彩与 Lanczos3 缩放，JPEG 输出采用 Jpegli 4:4:4 高画质编码。单次 JPG 输出通过 32 行像素条带直接流入 Jpegli，不再写入并回读中间 PNG；目标体积节点仍复用一份压缩的无损工作底图。工作流会延迟物化中间结果，非必要不重复编码 JPEG；FFmpeg 仅作为少数格式的兼容回退。

顶部“黑白优化”默认开启，仅在整张图被明确识别为黑白内容时改用单通道 JPG 编码；泛黄扫描、低饱和彩页和任何存在明确色差的图片保持彩色。“逆网点化”节点提供轻微、中度、强力三档 CPU 去网平滑。

“目标体积压缩”节点可设置目标 MB、起始画质、画质上限和画质下限。它使用真实编码采样、局部对数预测和批次历史提示，在最多 5 次尝试内选择不超过目标体积的最高已验证画质；所有候选都从同一工作底图编码，避免代际二次压缩。

ZIP 工作流提供“解压 ZIP”预处理节点和“打包 ZIP”后处理节点。批量 ZIP 会分别解压到源 ZIP 同目录下的同名文件夹；直接运行会自动完成预处理，精确预估则会先提示。后处理固定采用 Store/仅存储，不计算 ZIP 预估大小，并可在校验成功后替换原 ZIP。

纯筛选分支可以直接抵达“保存输出”：如果图片没有经过转换、缩放、压缩或逆网点化，运行结果标记为“不处理”并保留原文件，不强制改成 JPG；只要分支实际修改了图片，最终仍必须经过可生成 JPG 的节点。画布空白区域使用独立的高清张手/握手矢量光标，适配 Windows 高 DPI 显示。

“删除解压目录”后处理节点可接在 ZIP 压缩节点之后。它只会在新 ZIP 完成写入并通过读取校验后，永久删除本次解压节点创建并登记的对应文件夹；未登记目录、处理失败或打包失败的图包不会被删除。

替换原图时会先确认源文件已释放，再把回收站操作交给单一专用 STA 线程执行；ZIP 解压图片即使采用 8—16 路并行处理，也不会从多个线程同时进入 Windows Shell。临时 Shell 失败会自动短暂重试，持续失败时显示具体错误码。

## 构建

```powershell
.\build.ps1
.\build.ps1 -Publish
.\build.ps1 -Publish -SelfContained
.\publish-distributions.ps1
```

开发环境需要 .NET 6 SDK、Node.js 与 pnpm。`publish-distributions.ps1` 会分别生成免装 .NET 的便携版和需要 .NET 6 Desktop Runtime 的精简版；两者默认都不携带可选 FFmpeg 兼容组件。

源码仓库保留 Jpegli 编码器及其许可证，但不包含体积较大的可选 FFmpeg 二进制。仅在确实需要少数兼容格式时，将 `ffmpeg.exe` 放入 `vendor/ffmpeg/`，再使用 `-IncludeFfmpeg` 构建。

Windows 10/11 通常已随 Microsoft Edge 安装 WebView2 Runtime；若系统精简过该组件，启动时会给出明确提示。
